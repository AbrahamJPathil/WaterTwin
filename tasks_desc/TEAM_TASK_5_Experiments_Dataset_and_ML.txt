TEAM TASK 5 — EXPERIMENTS, DATASET & ML (v2)

HARDWARE UPDATE: the conductivity signal throughout is TDS (ppm), not raw
EC (µS/cm) — the bought probe is a 0–1000 ppm TDS module. Every dataset
column and experiment below is renamed accordingly. Two new things worth
experimenting on, specific to the actual hardware: (1) whether TDS/turbidity
readings reliably distinguish "chamber wet" from "chamber dry" now that
there's no dedicated level sensor, and (2) how close a TDS reading gets
pinned near 1000 ppm before it's genuinely useless.

2. Why you are needed

The project is research-oriented.

Eventually we need evidence for:

Does the water fingerprint work?
Can water events be separated from sensor problems?
Does acoustic sensing correlate with fouling?
Does cleaning improve sensor behavior?
Can an ML model outperform the baseline?
Can chamber-wet/dry be reliably detected from TDS/turbidity alone?

These cannot be answered by writing code alone.

9. Dataset E — Chamber wet/dry detection (new)

Since there's no dedicated level sensor, this dataset answers a real
engineering question, not just a modeling one.

Record TDS and turbidity readings across repeated wet ↔ dry transitions
(dip the probes, remove them, repeat), labeled:

WET
DRY
TRANSITIONING

Report whether a simple threshold on TDS, turbidity, or their combination
separates wet from dry cleanly, and how fast the reading settles after each
transition — that settling time becomes the `stabilization_time_ms` value
Task 1 needs. If no threshold separates them reliably, say so plainly; that
finding is what justifies adding a dedicated presence sensor later.

13. Important dataset rule

Never randomly split sequential data like:

row 1–800 → train
row 801–1000 → test

if those rows are from the same continuous experiment.

That can produce misleadingly good results.

Prefer:

Experiment 1 → training
Experiment 2 → validation
Experiment 3 → testing

or another experiment-level split.
